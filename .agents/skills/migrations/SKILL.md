# Migrations

`resourcey` derives SQLAlchemy models from resource metadata, and derives
migrations from those models.

## Autogeneration

* `resourcey migrate autogenerate -m "add foo resource"` introspects the
  current resource models, diffs them against the database, and writes an
  Alembic migration.
* Generated migrations are plain Alembic revisions — inspect and edit them
  like any hand-written migration. Never blindly apply an autogenerated
  migration without reviewing the diff.

## Transient dev mode

* In development, `resourcey` can run in **transient mode**: SQLAlchemy
  `create_all()` is run against the dev database on startup, so you can
  iterate on resource definitions without writing migrations.
* Transient mode must never be enabled in production. It is gated behind an
  explicit config flag (`RESOURCEY_TRANSIENT_SCHEMA=true`).

## Escape hatch

You can always run `alembic` directly — `alembic revision --autogenerate`,
`alembic upgrade head`, etc. The framework's migration commands wrap Alembic;
they do not replace it.
